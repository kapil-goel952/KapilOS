# KapilOS File Structure

## 1. Root Level
The root of the project contains the main source tree, assets, third-party libraries, build output, and documentation.

Typical top-level structure:

KapilOS/
- Source/
- Assets/
- ThirdParty/
- Build/
- Docs/

## 2. Source
This is the main KapilOS codebase.

### 2.1 Source/Core
Contains the entry-point and core build/runtime files.

Common purpose:
- application entry point
- version information
- system information
- logging
- configuration
- core build logic

### 2.2 Source/Graphics
Contains the SDL and rendering bootstrap layer.

Responsibilities:
- create window
- create renderer
- initialize SDL
- initialize SDL_image
- initialize ImGui
- run the main loop
- load and own the wallpaper texture
- shut everything down cleanly

### 2.3 Source/UI
Contains all UI-related modules.

This includes:
- Desktop
- TopBar
- Sidebar
- Dock
- Widgets
- Layout
- Theme
- UIManager
- Window system
- future panels and reusable UI elements

### 2.4 Source/ApplicationManager
Owns the desktop application system.

Responsibilities:
- manage app instances
- draw applications
- keep the application list organised
- support future launch flow

### 2.5 Source/Applications
Contains application code.

Current and future examples:
- Application base class
- File Explorer
- Settings
- future apps such as terminal, browser, notes, music player, etc.

### 2.6 Source/AssetManager
Contains the asset management layer.

Responsibilities:
- generate asset paths
- load textures through SDL_image
- later support caching, fonts, sounds, SVGs, and more

### 2.7 Source/UI/Layout
Contains responsive layout logic.

Responsibilities:
- screen size tracking
- responsive size calculations
- top bar height
- sidebar width
- dock size
- spacing
- padding
- icon sizes
- scaling helpers

### 2.8 Source/UI/Theme
Contains styling and theme logic.

Responsibilities:
- colours
- visual theme decisions
- rounding
- visual consistency

### 2.9 Source/UI/Widgets
Contains reusable UI widgets.

Current widgets and planned widgets can include:
- Weather
- Calendar
- Status
- Button
- Card
- Panel
- Search box
- Toast
- Menu items
- future controls

### 2.10 Source/UI/Desktop
Contains the desktop workspace UI.

Responsibilities:
- wallpaper-facing desktop area
- desktop items
- desktop background space
- transparent desktop window

### 2.11 Source/UI/TopBar
Contains the top system bar.

Responsibilities:
- title area
- clock
- system indicators
- future system controls

### 2.12 Source/UI/Sidebar
Contains the vertical system-navigation panel.

Responsibilities:
- home
- search
- files
- workspace
- notifications
- quick settings
- settings
- profile

### 2.13 Source/UI/Dock
Contains the bottom-centered dock.

Responsibilities:
- pinned applications
- running applications
- frequently used applications

### 2.14 Source/UI/UIManager
Contains the root UI controller.

Responsibilities:
- coordinate all permanent desktop UI
- create the DockSpace
- call desktop components every frame
- call ApplicationManager every frame

### 2.15 Source/UI/Window
Contains the window abstraction layer.

Responsibilities:
- window state
- title handling
- future custom window controls
- future fullscreen/maximize/minimize behaviour

### 2.16 Source/UI/Panels
Contains higher-level UI panels such as:
- search panel
- notification panel
- quick settings panel
- Kapil menu panel

This folder exists for future system panels and overlays.

## 3. Assets
This folder contains project resources.

### 3.1 Assets/Wallpapers
Default and future desktop wallpapers.

### 3.2 Assets/Icons
SVG, PNG, or future icon assets.

### 3.3 Assets/Fonts
Font files used by the UI and future text rendering systems.

### 3.4 Assets/Sounds
Sound resources for future system audio.

### 3.5 Assets/Cursors
Custom cursor assets if needed.

### 3.6 Assets/Images
General image assets.

### 3.7 Assets/Videos
Video or animation resources if needed in the future.

### 3.8 Assets/Mockups
Design references, UI previews, or visual plans.

### 3.9 Assets/Screenshots
Captured screenshots of the current system and UI states.

## 4. ThirdParty
Contains external libraries and vendors.

Current examples:
- imgui
- nanosvg

This folder should store prebuilt or externally maintained components that KapilOS depends on.

## 5. Build
Contains build output generated by CMake and make.

This folder should not be treated as source code.

## 6. Docs
Contains project documentation.

Current and planned documents:
- PROJECT_MANIFEST.md
- README.md
- ARCHITECTURE.md
- ROADMAP.md
- DEVELOPER_GUIDE.md
- CODING_STYLE.md
- CHANGELOG.md
- FILE_STRUCTURE.md

## 7. Directory Workflow Summary
Program flow in KapilOS generally follows this order:

main.cpp
-> Graphics
-> ImGui
-> UIManager
-> Desktop / TopBar / Sidebar / Dock / Widgets
-> ApplicationManager
-> Applications
-> Render to screen

Assets flow through AssetManager.
Responsive sizes flow through LayoutManager.
Styling flow through ThemeManager.

## 8. Structure Rules
- Do not place unrelated code in the wrong folder.
- Keep graphics code in Graphics.
- Keep layout logic in LayoutManager.
- Keep theme logic in ThemeManager.
- Keep reusable UI code inside UI/Widgets.
- Keep application code inside Applications.
- Keep asset handling inside AssetManager.
- Keep docs inside Docs.

## 9. Evolution Rule
This structure is expected to grow.
When a folder becomes too large, split it into smaller modules instead of mixing unrelated responsibilities together.
